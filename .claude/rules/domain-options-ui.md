# Options UI

- **Options** — standalone `CombatModeOptionsFrame` (`CM.OpenOptions` / `/acm`), not Blizzard settings; tabs wire to existing `CM.*` + `CM.DB` only. Advanced holds force-lock / force-unlock Lua, the crosshair situational appearance and condition, and the Reticle CVar + macro-preline editor buttons.
- **Crosshair Textures editor** — `UI/Editors/CrosshairTextureEditor.lua` (`CM.OpenCrosshairTextureEditor("main"|"situational")`): Inactive/Active slot cards, preset pairs, scrollable grid of every texture in `CM.Constants.CrosshairTextures` (curated + 202 pack TGAs under `Assets/crosshair/pack/`, regenerated with `scripts/art/import-crosshair-pack.ps1`). Appearance (Crosshair tab) and Situational Appearance (Advanced) are `ctx:Button{layout="row", previews=...}` rows that open it. Saved shape `{Name, Base, Active, BaseId, ActiveId}`; `InitDatabase` normalizes saves before `MergeDefaults` (which would otherwise graft default ids onto them). Each slot card has an eye button (`UI.CreateIconBadge`, pack-115/117) that hides that slot (catalog id `"none"`, empty path; both hidden in situational = `CrosshairSituationalHidden`). Main target also has Mounted and Disabled cards (`global.crosshairMountedId` / `crosshairTargetLockId`, default `"Dot"`; read by Crosshair.lua). Glyphs must stay white: the crosshair tints them.
- **Options search** — `UI/Options/OptionsSearch.lua`: title-bar box that indexes `Options.controls` by the `control.search` metadata the ctx layout attaches (label, desc, tab, segment group). New searchable options need a `label` (and optional `desc`) on their `ctx:` call; editor windows without a search context are not indexed. Navigation uses `Options.SelectTabById`, `Options.RegisterSegmentSelector` and `Options.GetTabScroll`.
- **Options preview:** tab `onSelect`/`onDeselect`; Crosshair → `CM.SetCrosshairOptionsPreview`; Ally Cycle → `CM.SetAllyCycleOptionsPreview`.
- **Theme:** warm dark palette in `UI/Options/Draw.lua` (`UI.Colors`): copper accent (`#D08A52`) for headers, selected tab, toggles on (`toggleOn`), input values and NEW badges; near-black brown panels with a warm-brown `cardBorder`; cream `text`. Use tokens, not literal RGB, in every window (options, dialogs, editors, changelog). `UI.StripColors` removes inline markup from option strings. Shared primitives in `Draw.lua` — reuse them, do not restyle per widget: `UI.StyleControl` + `UI.WireControlHover` (every button-like control; `"primary"` for the solid accent button), `UI.SetControlVariant` (switch a styled control to `"primary"` / `"danger"` / `"disabled"` / neutral) and `UI.SetControlAttention` (bright outline + sweeping shine for a call-to-action: What's New, wizard Finish, a keybind that is listening; dark label text on it needs `SetShadowOffset(0, 0)`), `UI.StyleField` (input wells), `UI.CreateZone` (window background zones), `UI.StyleWindow` (frame + shadow via `UI.AddWindowShadow`), `UI.CreateRoundedHover`, `UI.StyleRounded`. Title art is drawn at `CM.Constants.TitleSize(height)` (true ~2.7:1 aspect, not the 4:1 file).
- **Editors/Changelog load order:** standalone editors (`UI/Editors/*`) and the changelog panel load after the `UI/Options` toolkit they consume (`ChangelogNamespace.lua` → `ChangelogData.lua` → `ChangelogPanel.lua`). `ChangelogData.lua` is generated from `CombatMode/CHANGELOG.md` by `scripts/sync-changelog-to-lua.ps1`; never edit it by hand.
- **Wizard** — `UI/Wizard/Spotlight.lua` (`UI.ShowSpotlight`: dimmed screen with a hole around one widget plus an explanation balloon) → `SetupWizard.lua` (`CM.Wizard.Start`: a tour through the real options tabs via `Options.FocusControl`, one setting per step; per-step highlight, balloon and warning text). Steps with `slides = { key, count[, seconds per slide[, cross-fade seconds]] }` show screenshots (`Assets/wizard/<key>_<n>.blp`, 16:9 crops around the crosshair, 40% of the screenshot height (tighter for Crosshair / Assist HUD, `CROP_OVERRIDE`), stored squashed as 512x256 BLP2 DXT1 with mips and drawn back at 16:9) looping as a cross-faded slideshow under the balloon title, inside one shared frame overlay (`preview_frame.tga`, the README GIFs' metal band + shadow + copper glow). Both are built by `scripts/art/make-wizard-previews.py` from a folder of numbered full-screen screenshots; rerun it to change a set (update the step's count). Started by the first-login popup, or once at login for an account with `global.seenWizard == false` (`DisplayPopup` in Runtime.lua); `global.seenWarning`/`seenWizard` are account-wide (migrated from `char` in `InitDatabase`); finishing the tour opens the changelog if the version is unseen and the cog beside the version chip. New first-run-relevant options need a step or an update to the existing one.
- **New options are flagged "NEW"** — every new option gets `newFeatureFlag = true` on its control (Alliance badge) and the tab holding it gets `newFeatureFlag = true` in its `AddTab` definition (Horde badge on the tab button), even if the tab already shows one. Remove both only when a release retires them.
- **What's New** — `UI/Options/WhatsNew.lua`: window opened at screen centre like the other windows (frameless accent NEW-style button right of the version chip, shown by `Options.RefreshWhatsNewButton` on open) listing every option / section / tab flagged `newFeatureFlag`. It reads the registries (`control.search.newFeature` set by `TagSearch`, `sectionRec.newFeature`, `Options.tabDefs`), keeps no list of its own, and navigates through `Options.NavigateTo` (OptionsSearch.lua) without closing. The button is `UI.CreateWhatsNewButton` (Widgets.lua), also placed in the changelog window's title bar; a row clicked while the options window is closed opens it first.

**In-game checks:** setup wizard on a new character (or Debug Mode + `/reload`): every step scrolls, dims, outlines and its balloon stays on screen; action steps keep Next disabled until their keys are bound; combat delays the start and ends a running tour. New options appear in Options search and What's New with the NEW badge. Values persist through `/reload` in the intended scope (`global` vs `char`).
