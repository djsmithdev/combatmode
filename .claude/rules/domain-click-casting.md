# Click casting and Reticle Targeting

- **BindingOverrides** — click-cast / Target Lock secure buttons; Cycle Lock Next/Previous as dedicated Bindings.xml keys (`ApplyCycleFocusBindings` + `SetOverrideBindingClick`; defaults Shift+mouse-wheel). Macro slots skip the reticle proxy (`CM.GetDisplayedActionSlotInfo`); Bonus/Override/TempShapeshift macros use `SetOverrideBindingClick` on the live frame. On the keyboard proxy path, a key whose bar can show a Party Wheel spell is bound to `CombatModePartyWheelKey` instead (`CM.PartyWheelPrepareKey(bindingIndex, bindingName, macroText)` returns the button + click arg; unlisted spells forward to a route button running the same click-cast macro).
- **ComposedMacros** (`Core/ClickCasting/ComposedMacros.lua`) — the "Reticle Targeting Macros" shelf, an option below the spell lists on the Reticle Targeting tab (`TabReticleTargeting.lua`, `CM.EnumerateComposedMacros`) lists macros that open with an ACM preline as round icons; drag/click calls `PickupMacro` (out of combat) so players drop them on action bars (they then follow bar swaps), and its trailing "+" opens `UI/Editors/ComposedMacroEditor.lua`. The editor writes a real WoW macro = `CM.GetActiveTargetingPreline()` + user body (255 cap, no `/click` reserve) and remembers the body in `global.composedMacros[name]`; `RebuildComposedMacros` (from `RefreshClickCastMacros`) re-edits those macros when the preline changes. The Run MACRO dropdown lists existing macros (icon + Reticle Targeting tag) and just stores `macroName`. Never name macros with a `CM_` prefix (`RemoveLegacyMacros` deletes them).
- **Nested macro /click:** SecureActionButton `macrotext` cannot `/click` another macro button (silent no-op). Classify bar slots with `CM.GetDisplayedActionSlotInfo` (live frame action; reject stale override 121–132 after dismount; else page/bonus or MultiBar slot) — not hard-coded slots 1–12. **255 cap is on executed text (tested in game):** `macrotext` set from a `SecureHandlerBaseTemplate` OnClick snippet (M6-style inlining) is cut at 255 exactly like plain `macrotext`, so inlining the preline + a bar macro's body cannot beat the limit; it would only add the preline to short plain macros (preline ~125 chars) and was dropped. **Visible-slot probe (tested, dropped):** a `SecureHandlerBaseTemplate` OnClick snippet can read the visible bar button's slot live in combat (`id + GetEffectiveAttribute("actionpage")*12 - 12`, else its `action` attribute) and `GetActionInfo` it; on default bars across druid form swaps it matched `CM.GetDisplayedActionSlotInfo` on every press, for keyboard keys and click-cast mouse buttons, and helpful/harmful targeting was identical in and out of combat. The reported "stuck on bar 1" bug did not reproduce on default bars; Bartender4/Dominos/ElvUI were untested. Needed from a reporter before reopening: bar addon + version, key or mouse button, what was swapped (form/page/stance), combat only or not, and the slot's spell or macro.
- **M6 macros in Run MACRO (tested, dropped):** an M6 stub (`_M6+sXX`) fails as `MACRO name` (macro running a macro) and as `CLICK M6Prime:sXX` too: M6Prime's click wrap checks `RW:IsPyrolysisActive()` and prints "Cannot execute an M6 macro now". M6 only runs macros through its own `M6Bind!b<actionId>` proxies, which exist only for macros with a bind set in M6, and mapping a stub to that id has no public API. Tell M6 users to use M6's own conditional binding.
- **Help/harm routing (TargetingMacroBuilder):** helpful + Ignore Friendlies → no `/tar` (not keys-gated; Forever / unbound); helpful + Any → `/tar` `[help]` mouseover / `@softinteract` / `@anyfriend` (hostiles do not steal a friendly hard target); harmful → enemy `/tar` when cycle keys bound (including solo); no last-ally retarget except optional restore-after-harm. Restore-after-harm: slim harm `/tar` (keeps `[@focus,harm]`) + `/targetlasttarget [harm]` (`IsAllyCycleRestoreAfterHarm`; healer spec default until toggled; skipped when Auto Target Lock is on).
- Standalone editor windows (`UI/Editors/*`) register in `Embeds.xml` after the `UI/Options` toolkit; keep `CM.Open*` combat-guarded where frames are created. When changing reticle CVar presets or exclusions, update `Constants/CVars.lua`, `UI/Editors/ReticleCVarEditorData.lua` and `Core/Runtime/CVarManager.lua` together.
- **TargetingMacroBuilder** — builds the macrotext injected into click-cast proxies: `CM.BuildClickCastMacroText(bindingValue)` (no-op when `reticleTargeting` is off), preline variants (any / enemy-only × plain / auto-lock) with user overrides from `global.targetingMacroPreline*Override` (edited in `UI/Editors/TargetingMacroPrelinesEditor.lua`, effective after reload), optional ally-restore post-line, `/click` bar button or `/cast [@cursor]` for ground spells, and the cast-at-cursor / exclude spell lists. Hard limit: **255 characters** (`SECURE_MACROTEXT_MAX`); long macros fall back to `SLIMMER_PRELINE` (matters for ElvUI/Bartender with key-down). Auto-lock prelines also re-sync `/focus` so a sticky empty focus can't leave a dead lock.
- **AddonActionBarResolver** — maps ACTIONBUTTON / MULTIACTIONBAR1–7 to ElvUI / Bartender4 / Dominos button frames and forces `macroInjectionClickCastOnly` when those addons are loaded (caches cleared on binding refresh). It doesn't set bindings or build macro text.
